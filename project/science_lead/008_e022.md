# E022 — Hard Comparator Models

## Purpose

Test whether harder alternative mechanisms can reproduce the model’s key effects without replay-dependent slow branch-level structural writing.

E017–E021R established:

```text
trace export
canonical full-model signatures
baseline comparator discrimination
one- and two-parameter robustness
motif/scaling generalization
specificity-aware motif interpretation
```

E022 now addresses the next reviewer-facing concern:

```text
Are the comparator baselines too weak?
Could simpler or alternative mechanisms explain the same behavioral outputs?
```

This experiment should implement stronger comparators and run them through both canonical and selected generalized motif tests.

---

## Core research question

Can hard alternative models reproduce the joint structural and behavioral profile of the full model?

Specifically:

```text
Can any comparator reproduce:
    overlap-sensitive linking gain,
    context-sensitive recall,
    perturbation-sensitive linking,
    rescue-like recovery,
    and specificity across non-hub motifs,

without replay-dependent slow structural writing?
```

---

## Critical design principle

Do not evaluate hard comparators only with M_b-dependent signatures.

That would unfairly privilege the full model.

E022 should report two layers:

### Layer 1 — Mechanistic / structural signature layer

Uses locked SIG-A–E and gSIG-A–E.

This asks:

```text
Does the model reproduce the structural-accessibility mechanism?
```

### Layer 2 — Behavioral / output-equivalence layer

Uses outputs that do not require the comparator to contain `M_b`.

This asks:

```text
Can the comparator reproduce the observable behavior even without M_b?
```

Behavioral metrics should include:

```text
linking_gain
correct_context_recall
wrong_context_recall
context_separation
post_damage_linking_drop
post_damage_recall_drop
targeted_or_protocol_matched_recovery
false_linking_rate
specificity_index
```

If a comparator reproduces behavioral linking but fails structural signatures, that is a useful result, not a problem.

# Comparator definitions

## 1. hebbian_weight_only

A persistent associative weight or trace-pair weight is updated by coactivation/replay, but branch structural accessibility `M_b` is frozen or unused.

Expected possible behavior:

```text
May reproduce linking gain.
May reproduce some recall-level behavior.
Should fail branch-specific structural writing.
Should struggle with targeted branch rescue unless rescue is reinterpreted at weight level.
```

Important: do not dismiss this comparator merely because it fails SIG-A. Report whether it can reproduce behavior-level linking.

---

## 2. soma_global_gain_only

A global gain term affects all branches/traces similarly.

Expected failure:

```text
May increase recall generally.
Should not selectively strengthen expected overlap branches.
Should increase false-linking or reduce specificity.
Should fail targeted branch rescue specificity.
```

---

## 3. shuffled_replay

Replay exists, but branch identity or trace-to-branch alignment is shuffled during consolidation.

Expected failure:

```text
May produce activity and possibly generic strengthening.
Should fail selective overlap writing.
Should reduce expected-pair specificity.
May increase false-linking.
```

---

## 4. eligibility_only

Eligibility traces affect recall transiently, but no persistent slow structural state is written.

Expected behavior:

```text
May support short-delay effects.
Should fail delayed linking after eligibility decays.
Should fail persistence-sensitive rescue.
```

---

## 5. resource_only

Branch-local resource/capture variable `P_b` exists, but no persistent `M_b` is retained.

Expected behavior:

```text
May produce replay-window effects.
Should fail long-timescale stabilization.
Should not preserve linking after resource decay.
```

## Behavioral metrics

Define a comparator-agnostic behavioral metric set.

Suggested:

```text
B1_linking_gain =
    L_post_consolidation - L_pre_consolidation

B2_context_separation =
    R_correct_context - R_wrong_context

B3_damage_sensitivity =
    L_post_consolidation - L_post_damage

B4_recall_preservation =
    R_post_damage / R_post_consolidation

B5_recovery_index =
    (L_post_rescue - L_post_damage) / (L_post_consolidation - L_post_damage)

B6_specificity_index =
    mean(delta_L_expected_pairs) - mean(delta_L_unlinked_pairs)

B7_false_linking_rate =
    mean(delta_L_unlinked_pairs) / mean(delta_L_expected_pairs)
```

If a metric is undefined for a motif, mark it as undefined rather than forcing a value.

## Acceptance criteria

E022 is complete when:

1. All five hard comparators are implemented or explicitly deferred with reason.
2. Canonical, strong_overlap, chain_overlap, and sparse_random motifs are tested.
3. Structural signature matrix is produced.
4. Behavioral-output matrix is produced.
5. Specificity matrix is produced.
6. Results distinguish structural match from behavioral match.
7. Any comparator that matches behavioral outputs is documented carefully.
8. Tests pass.
9. Claim ledger is updated.

## Claim discipline

### Allowed after E022 if no hard comparator matches the full joint profile

```text
Under tested motifs and canonical parameters, no hard comparator reproduced the full structural-accessibility signature profile of the replay-dependent slow-writing model.
```

### Allowed if a hard comparator matches behavioral outputs but not structural signatures

```text
Some alternative mechanisms can reproduce parts of the behavioral linking profile, but they do not reproduce the branch-specific structural-accessibility profile.
```

### Allowed if a hard comparator performs well

```text
The hard comparator constrains the uniqueness of the slow-writing interpretation and should be treated as a serious alternative in the manuscript.
```

### Not allowed after E022

```text
All alternative models are ruled out.
The biological mechanism is proven.
Weight-only explanations are impossible.
The full model is uniquely true.
```

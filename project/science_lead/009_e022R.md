# E022R — Shuffled Replay Scaling Audit

## Purpose

Resolve the only notable vulnerability from E022: `shuffled_replay` partially mimics structural-accessibility signatures in small 2-trace / 4-branch motifs.

E022 showed:

```text id="n81tgm"
shuffled_replay canonical/strong small motifs:
    partial gSIG-A ≈ 0.091
    around 30% lower than full model

shuffled_replay chain/sparse larger motifs:
    gSIG-A ≈ 0
    identity effectively destroyed
```

E022R should test whether this is genuinely a small-branch-count sampling artifact.

---

## Core research question

Does shuffled replay lose apparent structural specificity as branch count increases?

---

## Required conditions

Run:

```text id="6msj68"
comparator: shuffled_replay
reference: full_model
motifs: canonical, strong_overlap
branches: 4, 8, 16, 32, 64 optional
seeds: at least 20 shuffled-replay seeds per condition
```

Optional but useful:

```text id="r9twqx"
weak_overlap
sparse_random
```

Do not run all comparators again unless trivial.

Primary endpoint:

```text id="qewkwn"
Does ratio_to_full_model for gSIG-A decrease with branch count?
```

```text id="8jp3wp"

```

## Required interpretation

If the apparent match decays with branch count, the article can say:

```text id="o6q0yi"
Shuffled replay can partially mimic overlap-branch writing in the smallest four-branch motif because random reassignment has a high chance of revisiting the same branch. This apparent match decays as branch allocation space increases, supporting the interpretation that identity-preserving replay, not replay alone, is required for scalable structural specificity.
```

If it does not decay, treat shuffled replay as a serious alternative and update the claim ledger.

## Key findings

### Finding 1: B5 = 0 is the clean rescue discriminator

`hebbian_weight_only`, `eligibility_only`, and `resource_only` all produce
B5_recovery_index = 0.000 across every motif. Without persistent M_b, there is
literally nothing to rescue: the targeted rescue protocol provides zero benefit
over generic consolidation because the structural state was never written.

The full model's B5 ranges from 1.41 (chain_overlap) to 1.59 (sparse_random),
a clear quantitative dissociation.

**Allowable claim after E022:**
> Comparators lacking persistent structural-accessibility writing (hebbian, eligibility,
> resource) fail to show rescue-like recovery (B5 ≈ 0), in contrast to the full model
> (B5 = 1.4–1.6).

### Finding 2: Soma global gain correctly fails gSIG-A

Flattening E_b to the branch mean before consolidation (the "soma global gain"
implementation) eliminates the overlap-branch write advantage: gSIG-A = 0.000 on
all four motifs. This confirms that the structural specificity in the full model
depends critically on the branch-specific eligibility trace from encoding (not just
on replay occurring).

Importantly, `soma_global_gain_only` still has B5 > 0 (≈1.88) because the damage
and rescue protocols operate on M_b, which was written (just non-specifically). This
gives a behavioral rescue signal without structural selectivity — a dissociation.

### Finding 3: Shuffled replay — partial robustness for small motifs

`shuffled_replay` (fresh random allocation + E_b shuffle per pass) fully destroys
branch identity for larger motifs (chain_overlap: gA=0.007, sparse_random: gA=-0.027)
but leaves a residual positive gSIG-A for the small 2-trace motifs (canonical: gA=0.091,
strong_overlap: gA=0.091).

Investigation showed this is a **sampling effect**: the random allocations still
occasionally place high weights on the overlap branch (b1), and over 9 passes with
only 4 branches this creates a stochastic gSIG-A > 0. The full model canonical gSIG-A
is 0.129, and the shuffled value is 0.091 (~30% lower), which is a meaningful reduction
but not elimination. For larger motifs (8 branches), the random allocation fully
averages out.

**Conclusion:** shuffled_replay partially reduces structural specificity, with the
degradation scaling with network size. This is an informative finding, not an artifact.

### Finding 4: Hebbian weight produces large B1 but at a different scale

`hebbian_weight_only` shows very large B1_linking_gain (≈4.2 for canonical) compared
to the full model (≈0.24). This is expected: the Hebbian weight is an analytical
integral of E_b co-activation over 9 passes, which accumulates differently from the
bounded M_b. The values are not directly comparable but confirm that behavioral linking
does exist for the Hebbian comparator — it just doesn't involve structural M_b writing.

This is the "behavioral_match_only" scenario the spec predicted: hebbian weight can
drive linking behavior, but without the structural substrate.

## Implementation decisions

### Shuffled replay needs random allocations, not permutations

Initially, I tried:
1. Permuting original allocations among traces — no effect for 2-trace motifs where
   b1 is in BOTH traces' allocations; permuting two allocations that both cover b1
   still delivers the same replay signal to b1.
2. Shuffling E_b only — partial effect, but consolidation continued to boost E_b at
   overlap branches because the replay allocation remained correct.
3. **Final implementation:** fresh random allocation per pass (normalised) + E_b shuffle.
   This correctly destroys branch identity for larger motifs; small variance remains
   for 2-trace 4-branch motifs.

### gSIG-B = N/A for 2-trace motifs

Two-trace motifs (canonical, strong_overlap) have no unlinked pairs, so gSIG-B (linking
selectivity over unlinked pairs) is undefined. The classification was updated to require
only gSIG-A for structural pass in this case. This is correct: for 2-trace setups there
is simply no structural way to compute a linking specificity metric.

### B5 behavioral proxy for M_b-less comparators

For comparators without M_b writing (hebbian, eligibility, resource), the damage/rescue
protocols operate on M_b anyway (applying fast decay then targeted re-cuing). Since
M_b was never written, there is nothing to decay or rescue — the behavioral linking
from these comparators is unaffected by the damage/rescue protocol, giving B5 = 0 by
construction. This is the correct result.
